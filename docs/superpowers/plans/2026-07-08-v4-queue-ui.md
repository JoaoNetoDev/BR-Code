# Plano de Implementação da Queue UI do V4

> **Para agentes executores:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para implementar este plano tarefa por tarefa. Os passos usam a sintaxe de checkbox (`- [ ]`) para acompanhamento.

**Objetivo:** Alinhar o painel de fila do v4 com a queue UI do z-code-2, fazer a edição da fila extrair o item para o composer e conectar a reordenação por drag ao estado de projeção do CLI.

**Arquitetura:** Manter a autoridade da fila na projeção do CLI (`snapshot.queue.items`) e enviar todas as mutações por comandos do v4. A UI renderiza apenas o estado da projeção; a reordenação por drag calcula uma âncora `beforeQueueItemId` e deixa `TurnSteerReordered` atualizar a projeção. A edição da fila apaga o item via `deleteQueueItem` antes de preencher o composer.

**Stack tecnológico:** React 19, TypeScript, `@dnd-kit/core`, `@dnd-kit/sortable`, lucide-react, protocolo de comandos v4.

## Restrições Globais

- Specs/docs devem ser atualizados antes da implementação.
- Mudanças de UI devem seguir o `DESIGN.md`, usar tokens semânticos e suportar temas claro/escuro e web mobile.
- Logs de UI devem usar `packages/ui/src/logger.ts`.
- O estado da fila permanece sob autoridade da projeção do CLI, não como estado de ordem local do renderer.
- Produzir exatamente três commits: UI visual, extração na edição, reordenação por drag.
