# Casos de aceitação manual de Conversation Session E2E

Este documento organiza os caminhos principais A–J de conversation session, além das matrizes especializadas de goal, fork, queue, compact, modelo, edit e subagent, em uma visão voltada a produto, desenvolvimento e QA. Cada caso mantém apenas três coisas: como o usuário opera, o que deve ser visto e onde rastrear o status de automação. Falhas de ambiente, UI puramente exibitiva, o produto cartesiano completo de ferramentas e testes de carga de desempenho permanecem em seus catálogos especializados e não são misturados a esta lista de aceitação manual do caminho principal.

A definição autoritativa dos cases continua em [Conversation Session Case Catalog](../conversation-session-case-catalog.md), e o status de automação continua em [Conversation Session E2E Coverage Matrix](./conversation-session-e2e-coverage-matrix.md). Este documento não redefine a semântica de produto; quando o status do documento original mudar, esta observação deve ser atualizada junto.

Significado dos status nas observações: coberto corresponde a `covered`, parcial a `partial`, planejado a
`planned/pending`, faltando a `missing` e podado a `pruned`. Quando a observação diz apenas «produto accepted», isso
significa que a semântica de produto já foi confirmada e não que o E2E já está coberto. Quando uma mesma linha
funde múltiplos cases equivalentes, a observação mantém todos os IDs originais.

```text
rascunho -> em execução -> entradas seguintes entram na fila -> turno atual concluído
                              |               |
                              |               +-> consumo automático / Goal continua / compactação automática
                              +-> Stop -> fila pausada -> continuar / enviar agora / reverter a edição

sessao pai -> Agent/Subagent child -> notificação de conclusão em segundo plano -> sessão pai continua
   |              |
   |              +-> detalhe somente leitura à direita / catálogo de subagentes
   +-> fork copia apenas o histórico estável, sem copiar queue nem estado de execução em segundo plano
```

## 1. Ciclo de vida básico da sessão

| Caminho de operação                                              | Resultado esperado                                                                                | Observação                     |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------ |
| Nova conversa → digitar texto comum → clicar em enviar            | Cria a session e entra na página de sessão real; a mensagem do usuário fica visível e a sessão entra em prewarm ou em execução | Origem: A01; coberto |
| Primeira mensagem recém-enviada, ainda em prewarm → enviar mais um texto comum | A segunda entrada entra na fila, sem interromper o primeiro turno                        | Origem: A02; coberto |
| Primeiro envio do rascunho já aceito → sessionId vinculado, mas a primeira mensagem autoritativa ainda não chegou | A caixa de entrada só se move do layout centralizado para o rodapé; a instância do editor e o conteúdo são contínuos; a timeline não fabrica mensagem de usuário nem mostra dica de estado vazio | Origem: A11; parcial |
| Sessão em execução, fila vazia → aguardar o assistant concluir normalmente | A sessão entra em estado concluído e a caixa de entrada volta a poder enviar                 | Origem: C01; coberto |
| Sessão concluída, fila vazia → continuar enviando texto comum     | Inicia imediatamente o próximo turno                                                          | Origem: C03; coberto |
| Em execução, fila vazia → clicar em parar → enviar texto comum    | O turno atual encerra como «已中断»; a mensagem seguinte inicia imediatamente um novo turno e não é enfileirada por engano com base no estado antigo | Origem: B01, B05, B12; coberto |
| Session A em execução → alternar para Session B → enviar mensagem em B | A continua em segundo plano e B também roda de forma independente; timeline, fila e estado dos dois lados não se sobrepõem | Origem: J01, J02, J04; coberto |
| A e B em execução → criar ou alternar para C e enviar             | C também pode executar; a camada de produto não limita o número de sessões concorrentes          | Origem: J03; coberto |

## 2. Fila e Stop

| Caminho de operação                                                                 | Resultado esperado                                                                                                          | Observação                       |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| Turno atual em execução → enviar 1, 2, 3 e mais textos comuns consecutivos            | Cada entrada é adicionada à mesma FIFO pela ordem de aceitação; o turno atual não é interrompido e `3+` pode ser exibido recolhido | Origem: A03-A06; coberto |
| Turno atual em execução → enviar `/goal ...`                                        | O comando é primeiro exibido como item de fila do tipo goal; só ao chegar a vez dele o objetivo é definido ou atualizado          | Origem: A07, H03, H04; coberto   |
| Turno atual em execução → enviar `/compact`                                          | `/compact` entra na fila como item de manutenção do tipo compact e avisa que foi enfileirado; não aparece como mensagem de usuário comum nem inicia compactação paralela | Origem: A08, M04, G1-03; planejado |
| Turno atual em execução → enviar, em sequência, texto comum, `/goal ...`, `/compact`            | Os três tipos de entrada compartilham a mesma ordem de aceitação; no consumo seguem respectivamente as semânticas originais de texto, goal e compact, sem misturar tipos | Origem: M05, G1-09; planejado |
| Durante a execução já há 1, 2 ou `3+` itens na fila → clicar em parar                 | O turno atual é interrompido; todos os itens da fila são preservados como estão e o consumo automático é desligado        | Origem: B02-B04; coberto         |
| Turno atual em execução, fila não vazia e consumo automático ligado → o turno conclui normalmente | O primeiro item é promovido automaticamente e o próximo turno começa; o texto consumido precisa se tornar uma mensagem de usuário real e visível, não apenas sumir da fila | Origem: C02; coberto |
| Existe fila pausada → enviar texto comum na caixa de entrada                        | Aparece a confirmação de disposição da fila: pode limpar a fila antiga e enviar, ou manter a fila antiga e enviar imediatamente; ao cancelar, o rascunho e os anexos não se perdem | Origem: B06, C08; parcial |
| Existe fila pausada → enviar `/goal <novo objetivo>`                                 | Compartilha a confirmação de disposição da fila com o texto comum; comandos de controle de objetivo como `/goal resume` não passam por essa confirmação | Origem: B07; parcial |
| Existe fila pausada → clicar em «立即发送» em um item da fila                        | Primero trava o item alvo e só então inicia atravessando a barreira de stop; o item original só é removido se o início for bem-sucedido e, em caso de falha ou timeout, permanece no lugar; a ordem relativa dos demais itens não muda | Origem: B08, M07a, M07b; parcial |
| Clicar duas vezes rapidamente em «立即发送» durante a execução                       | O mesmo item da fila é enviado no máximo uma vez, sem pedir de novo nem remover por engano um item vizinho          | Origem: M07g; atualmente failing, requer regressão |
| Fila pausada e caixa de entrada completamente vazia → clicar em «编辑» em um item de texto comum | Remove primeiro da fila autoritativa; após o sucesso, o texto original completo é restaurado apenas na caixa de entrada da session onde a ação foi iniciada, sem envio automático | Origem: B09; parcial |
| Fila pausada e caixa de entrada vazia → editar um item de goal da fila               | É restaurado como texto `/goal ...` completo; ao enviar de novo, obtém uma nova identidade de item de fila             | Origem: B09a, B09e; coberto      |
| Item da fila pausada com vários anexos → clicar em editar → reenviar direto           | A ordem e as referências originais dos anexos são totalmente restauradas, sem reenvio nem adopt duplicado; o novo envio gera um novo commandId e queueItemId | Origem: B09b, B09e; coberto |
| O item da fila é `/compact` → ver as operações disponíveis                           | Permite remover, reordenar ou executar imediatamente, mas não oferece entrada de edição de texto de volta para a caixa de entrada | Origem: B09f, B13; podado |
| A caixa de entrada já tem texto, anexos, contexto de web, referência de seleção ou upload em andamento → clicar em «editar» no item da fila | Recusa a retirada e não envia comando de remoção; o rascunho atual e a fila permanecem inalterados, com a dica de tratar primeiro o rascunho atual | Origem: B09c; coberto |
| Depois de clicar em «editar» em um item da fila, a outra ponta consome ou apaga o item, ou o lado local troca de session/workspace | Em stale/noop/falha o rascunho antigo não é restaurado; só se restaura idempotentemente quando é accepted/duplicate e ainda está na session e workspaceKey originais | Origem: B09d; parcial |
| A confirmação de disposição da fila já está aberta → a outra ponta adiciona, remove ou retira um item da fila → o lado local confirma o envio | A confirmação antiga fica inválida e não limpa itens novos que o usuário não viu; a confirmação é refeita com base na projeção mais recente. Apenas reordenar o mesmo lote de IDs não invalida a confirmação | Origem: B16; planejado |
| Fila pausada → arrastar para reordenar ou remover um item                              | Apenas muda a ordem autoritativa da fila ou remove o item alvo, sem disparar consumo                            | Origem: B10, B11; coberto       |
| Fila pausada e alvo já concluído ou inexistente → clicar em «继续»                    | Abre o consumo automático e consome da cabeça até o fim por FIFO; goal e compact mantêm seus respectivos tipos | Origem: B14; parcial |
| O turno principal ainda está em execução e a fila está pausada → clicar em «继续»     | Só liga o consumo automático, sem preemptar o turno atual; o consumo a partir da cabeça acontece depois que o turno atual encerra | Origem: B15; coberto |
| Desktop e celular enviam entrada ao mesmo tempo para a mesma session busy             | Todas as entradas aceitas são ordenadas em série pela mesma fila da CLI; o continuous do desktop e o replayable do celular só afetam a forma de entrega e não formam duas filas | Origem: PV4-03; falta evidência formal completa |
| Antes do reinício da CLI há entradas aceitas que ainda não entraram em estado terminal → reconectar ou consultar o resultado de comandos | As entradas são marcadas explicitamente como discarded; `queue/guide` são liquidadas silenciosamente, e apenas `startNow`/`unknown` que não entraram no transcript podem ser reenviados com um novo commandId após confirmação; o replay automático é proibido | Origem: PV4-06, PV4-25; especialização de protocolo |

## 3. Goal

| Caminho de operação                                                                             | Resultado esperado                                                                                                | Observação                                              |
| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Sessão concluída e sem goal → enviar `/goal 修完登录流程`                                      | Cria o objetivo; a timeline mostra imediatamente uma mensagem de usuário real idêntica ao comando original, e o resumo do objetivo exibe o objective analisado | Origem: C04, H01, G0-01; coberto |
| Já existe goal → enviar `/goal replace 修完登录流程`                                           | Substitui o objetivo, removendo do objective o prefixo do comando e `replace`; o comando original continua exibido como mensagem de usuário na íntegra | Origem: H02, G0-02; coberto |
| Compactação manual ou automática em andamento → enviar `/goal ...`                             | A entrada de goal entra na future queue; o objetivo só é atualizado e a mensagem real de usuário só é exibida quando a compactação terminar e chegar a vez dela | Origem: H05, G2-01, G2-07; caminho principal coberto; a especialização de auto teve registros failing que exigem regressão contínua |
| goal continuation ou verifier em execução → enviar texto comum, `/goal ...`, `/compact`      | As três entradas vão para a future queue e não iniciam requisições paralelas na mesma session                          | Origem: H06, H12, G1-14; H06 coberto, H12 planejado        |
| O mesmo objetivo passa por várias rodadas de execução e verificação → definir um novo objetivo | Cada rodada mostra apenas uma linha de verificação logo após o assistant correspondente; o novo objetivo começa na rodada 1 e não se mistura ao antigo | Origem: H07; coberto |
| Objetivo active/paused/budget-limited não concluído, fila não vazia → uma rodada do verifier termina ou clica em «继续» na fila | A fila continua sem ser consumida; a aprovação explícita ou o fail-open precisa primeiro atualizar o target para complete, e só então o consumo por FIFO acontece; cancelamento manual não conta como aprovação | Origem: H08, G1-10; faltando |
| goal verifier está requesting → clicar em parar → enviar texto comum                         | O verifier é encerrado e o estado de execução principal é limpo; o novo texto entra imediatamente em uma nova requisição ao provider e não fica bloqueado por um verifier residual | Origem: H09; coberto |
| goal verifier já parado → `/compact` manual → após a compactação enviar texto comum         | A compactação e o envio seguinte são permitidos, sem bloqueio pelo verifier antigo nem pelo lock de goal active antigo | Origem: H10; coberto |
| Modo guide, goal verifier em execução → enviar texto de guiado                                 | O verifier não pode ser steered; a mesma entrada preserva sua identidade e volta para a future queue, sem se perder, parar o objetivo ou disparar requisições paralelas | Origem: H11, G1-14; parcial |
| goal active → clicar em pausar no resumo                                                    | O objetivo entra em paused e o tempo acumulado é congelado; se houver goal work atual, ele é encerrado, mas a fila não é limpa nem consumida pelas regras normais de Stop | Origem: H13, G0-07; coberto |
| goal paused → clicar no triângulo de continuar                                                | O objetivo volta a active, o tempo acumulado não zera e a continuação segue pelo goal continuation original       | Origem: H14, G0-08; coberto |
| goal concluído → abrir ou restaurar o painel de status                                        | Mostra o tempo congelado e o ícone verde de conclusão, sem pausar/continuar; o live do desktop e o resultado após restauração são consistentes | Origem: H15, H16, G0-09, G0-10; parcial |
| Modo Plan → submeter `/goal` ou um alias no composer                                         | Apenas avisa que goal não está disponível no modo Plan; preserva o texto original, não cria session, não escreve histórico e não envia goal command | Origem: PG01, G0-11; coberto |
| Session A tem goal active/queued → alternar para B → voltar para A                          | B não mostra o objetivo nem a fila de A; ao voltar para A, o target e o goal queued de A são restaurados; uma session nova não herda histórico de goal/queue | Origem: G4-01-G4-04; coberto |
| goal queued aguardando consumo → trocar o modelo ou a profundidade de pensamento na session atual | Quando o goal realmente executar, ele usa a configuração de modelo mais recente da session atual                         | Origem: G1-08, N02; coberto |

## 4. Fork

| Caminho de operação                                                                                    | Resultado esperado                                                                                                              | Observação                  |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| Sessão concluída → clicar em fork sobre a mensagem final estável do assistant                        | Cria a session child; copia o histórico visível até o ponto de fork e a configuração nesse ponto, com a fila do child vazia | Origem: C06, E01, FX01; coberto |
| Resposta em streaming do assistant interrompida por Stop → tentar fazer fork do partial interrompido | A entrada de fork fica indisponível ou o comando é rejeitado; nenhum child é criado e a fila do pai permanece pausada | Origem: E02, E03, FX02; coberto |
| Tentar fazer fork de uma user message, tool block ou timeline marker                            | Nenhuma entrada de fork é oferecida e nenhum child é criado                                                                    | Origem: E04, E05, FX05; coberto |
| Session pai em execução, mas já havia um assistant estável antes → fazer fork dessa mensagem estável | O child copia apenas o prefixo estável; o primary/subagent/goal work atual do pai, a fila e o workspace continuam rodando como estavam | Origem: A09, E06, FX06; parcial |
| Session pai já tinha goal antes do ponto de fork e ainda tem fila → fazer fork do assistant estável | O child herda target, iteration e timeline de verifier anteriores ao ponto de fork; a fila do pai é preservada e a do child fica vazia | Origem: E07, FX03, G3-07; coberto |
| O assistant só tem partial failed/error e nenhum estado concluído estável → tentar fork             | A entrada de fork fica indisponível ou o comando é rejeitado; nenhuma timeline de fork é escrita                               | Origem: E08, FX04; faltando         |
| Editar a última mensagem de usuário e concluir o rerun → fazer fork do assistant do novo ramo    | O child contém apenas o ramo ativo editado, sem os ramos antigos de user/assistant que foram rebobinados                        | Origem: E09, FX07; coberto      |
| Dentro de um turno lógico há chamadas de ferramenta e alterações de arquivos, e só por último vem o texto do assistant → fazer fork do assistant final visível | O child copia o turno lógico inteiro: resposta final, blocos de ferramenta correspondentes e os fatos de arquivo já produzidos naquele turno, sem truncar a partir do assistant raw do meio | Origem: E10, FX08; coberto |
| Session pai tem background Bash/subagent em execução ou resultado de segundo plano não consumido → fazer fork do assistant estável | O child não copia live background work, pending result nem continuation inbox; a conclusão em segundo plano só acorda a session pai | Origem: FX09, K02; faltando |
| Compactação em execução → tentar fork; ou tentar fork de um assistant ainda não encerrado         | O compact operation lock rejeita o fork; um assistant atual em streaming/interrupted/failed/middle também não pode ser forkado, mas as regras de um target estável mais antigo permanecem inalteradas | Origem: FX10, PV4-14; parcial |

## 5. Edit e reset da conversa

| Caminho de operação                                                                          | Resultado esperado                                                                                                   | Observação                        |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| Sessão concluída → clicar em Edit na última mensagem real de usuário → modificar → enviar na linha | A session original roda de novo a partir daquela entrada e o histórico posterior é substituído pelo novo ramo ativo; o rascunho da caixa de entrada principal não participa deste edit | Origem: C07, D01; coberto |
| Há active work em execução → editar a última mensagem real de usuário e submeter                | Primeiro atravessa a barreira de Stop para que o work atual chegue a estado terminal, depois roda de novo na session original com o tipo de entrada original; a fila existente é preservada e não é consumida automaticamente | Origem: A10, PV4-13; planejado |
| Assistant interrompido por Stop → editar a mensagem de usuário enviada correspondente e submeter | A mensagem original é localizada pelo messageId estável e roda de novo imediatamente; a resposta interrompida é substituída pelo novo ramo, sem erro de resolução de turnIndex | Origem: D02, D10; coberto |
| Sessão interrompida com fila pausada → editar a última mensagem real de usuário                  | O edit roda de novo, e os IDs, a ordem e o conteúdo da fila são preservados como estão, com o consumo automático ainda desligado | Origem: D03, PV4-20; coberto |
| O rerun do edit está em execução → enviar texto comum, `/goal ...`, `/compact`                 | As três entradas vão para a future queue sem interromper o rerun atual do edit; o compact só é executado quando chegar a vez | Origem: D04-D06; texto/goal cobertos, compact planejado |
| Durante o rerun do edit → editar novamente a última mensagem real de usuário                   | Para primeiro o rerun atual e roda de novo com o texto de edit mais recente; a fila é preservada                              | Origem: D07; coberto              |
| Tentar fazer Edit de uma entrada real de usuário que não é a latest                             | A UI não oferece entrada ou o comando é rejeitado, e o ramo ativo não pode voltar a uma entrada mais antiga | Origem: D11, PV4-10; falta evidência formal de UI + command |
| Tentar fazer Edit de um assistant ou de uma tool message                                       | Nenhuma entrada de Edit é oferecida                                                                                       | Origem: D08, D09; coberto         |
| A latest entrada é `/goal ...` → clicar no Edit unificado → modificar e submeter                 | Continua sendo reproduzida como intenção de goal, atualizando target/iteration; não pode degenerar em texto comum nem gerar um goal marker extra | Origem: PV4-12, PV4-13; planejado |
| A latest entrada já foi coberta por um ou mais compact summary → fazer Edit e submeter          | Faz um corte de ramo append-only na session original; o registro antigo é preservado, mas sai da projeção ativa, e o estado derivado de do compact invalidado não entra mais no contexto do modelo | Origem: PV4-11, PV4-19; coberto |
| A latest entrada coberta por compact tem anexos → editar o texto e submeter preservando os anexos | Reproduz a intenção completa de anexos; não relê o workspace, não perde anexos e não cria child                                  | Origem: PV4-18; coberto           |
| O latest turno tem um checkpoint seguro de arquivos → escolher «对话 + 文件重置»                  | Restaura os arquivos em ordem inversa, corta a conversa e reenvia na session original; não cria child e não apresenta estados intermediários de sucesso apenas do workspace | Origem: PV4-21; coberto |
| O arquivo foi modificado externamente ou o checkpoint não é seguro → tentar o reset combinado → escolher «仅重置对话并发送» | A primeira operação é bloqueada de forma estruturada e arquivo/conversa ficam inalterados; a operação degradada usa um novo commandId e apenas reseta a conversa e reenvia | Origem: PV4-22; parcial |
| O turno cortado iniciou background Bash/subagent → editar a latest entrada                      | Primeiro cancela o trabalho de segundo plano cancelável daquele turno; se o cancelamento não puder ser confirmado, a operação inteira falha; uma completion atrasada não pode entrar no novo ramo, na fila, na UI nem no contexto do modelo | Origem: PV4-23; coberto |

## 6. Compact

| Caminho de operação                                                                    | Resultado esperado                                                                                                              | Observação                                    |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| Sessão concluída ou interrompida, fila vazia → `/compact` manual                        | Entra na compactação manual e mostra o started marker; após o sucesso o marker vira success e a sessão volta a poder continuar | Origem: C05, F01, F02, F08; coberto |
| Existe fila pausada → `/compact` manual                                                 | O compact é acrescentado ao fim da fila e permanece pausado; não abre a confirmação de disposição de texto e não envia imediatamente a requisição de compactação | Origem: B13, C09, F03; planejado |
| O turno atual ou um subagent/goal work de foreground está em execução → `/compact` manual | Entra estritamente na FIFO como item do tipo compact, sem parar o work atual; o lifecycle de compact só é entered quando chegar a vez | Origem: A08, H12, compact worksheet; planejado |
| Compactação manual em execução → enviar texto comum ou `/goal ...`                      | A nova entrada entra na future queue e não interrompe a compactação                                                               | Origem: F04, F05; coberto        |
| Compactação em execução ou já existe compact na fila → enviar `/compact` novamente      | Rejeita explicitamente avisando que já existe compactação; não cria novo item de fila, não inicia uma segunda requisição e não mostra mensagem de usuário comum | Origem: F06, G07; coberto |
| Compactação manual em execução → clicar em Stop                                         | O marker fica marcado como interrupted; a sessão entra em completed(interrupted), a fila é preservada como está e o consumo automático fica pausado | Origem: F07; faltando |
| Falha na requisição de compactação manual                                               | Não há retry automático; volta ao estado completed anterior ao compact, preservando queue e autoDrain; mostra o marker failed e a entrada de retry, e texto/goal/fork/edit/novo compact ficam todos restaurados | Origem: F09; decidido no produto; falta E2E |
| Envio comum, texto da cabeça da fila, goal queued ou rerun de edit prestes a executar → o sistema julga que precisa de compactação automática | Compacta primeiro automaticamente; após o sucesso continua a pendingAction original, e a ordem não pode ser invertida | Origem: G01-G04; parcial, a janela real de disparo ainda precisa de um fixture estável |
| Compactação automática em execução → enviar texto comum ou `/goal ...`                  | A entrada entra na future queue; a pendingAction só é consumida por FIFO depois de ser concluída                           | Origem: G05, G06; coberto        |
| Os summaries de compactação automática 1 e 2 são inválidos e o 3 tem sucesso               | No máximo 3 tentativas; a pendingAction é mantida o tempo todo e, após o 3º sucesso, a execução continua                   | Origem: G08-G10; coberto         |
| Três falhas consecutivas de compactação automática                                      | Mantém o marker retrying/failed, mas continua executando a pendingAction sem compactação; o circuit breaker atua, e a contagem é zerada após uma compactação manual bem-sucedida | Origem: G11; decidido no produto; falta E2E |
| Compactação automática em execução → clicar em Stop                                    | Alinhado ao Stop comum: a pendingAction é mantida como entrada de usuário do turno interrompido em curso, sem voltar para a fila; todos os itens explicitamente acrescentados à fila são preservados e o consumo fica pausado | Origem: G12; decidido no produto; falta E2E |
| Um compact manual queued teve um auto compact pouco antes de chegar a vez                 | Continua sendo executado conforme a intenção explícita do usuário; o runtime pode devolver um marker noop, mas não pode apagar silenciosamente esse item da fila | Origem: compact worksheet; accepted, precisa ser verificado junto com o caso de typed queue |

## 7. Troca de modelo, profundidade de pensamento e configuração do rascunho
