# Viewport de livre dimension no navegador embutido

> O supplemento de 2026-09-07 sobre coordenadas e contrato de reconexão via CDP está em [spec de coordenadas de zoom do Desktop](2026-09-07-desktop-zoom-coordinate-spec.md): preserva a compensação de raster, e a entrada é convertida conforme a escala de métricas já aplicada; o Main normaliza o zoom do guest ao definir/reproduzir o viewport, e o replay não pode ser pulado dentro da janela crítica de captura.
>
> Desde 2026-10-16, os níveis de ampliação também passaram a usar compensação de layout no renderer (layout do webview ×1/zoom + scale(zoom)); as métricas do CDP não carregam mais escala e a entrada não é mais multiplicada; abaixo, a seção de 2026-07-22 "compensação de ampliação nos guest metrics" foi substituída, e o motivo está na mesma spec, em "a página cresce e encolhe após o detach ocioso do CDP".

Data: 2026-07-15 (2026-07-16 supplementa pixels de captura, reentrada por timeout e semântica da cadeia de rolagem horizontal; 2026-07-17 suplementa entradas de tamanho no topo, zoom de pré-visualização, viewport alto, feedback fora de faixa, Fit padrão, cadeia de rolagem vertical, semântica silenciosa de abertura/resize pelo modelo, isolamento do zoom global e cobertura/compensação de layout reduzido da camada de composição do guest; 2026-07-20 suplementa o desacoplamento entre a surface visível no host Retina e as métricas de página com DPR=1, a distinção da origem de criação por tab, a autocorreção do tamanho raster da captura, o baseline CSS 1× do primeiro frame da captura e o downsample de alta qualidade no host para dimensões dinâmicas; 2026-07-22 suplementa o re-teste dinâmico do Fit com o zoom do Desktop, corrige o falso positivo de transform tardio em favor de compensação de ampliação nos guest metrics, e trava a normalização do zoom do guest após a conclusão das métricas; 2026-07-24 suplementa a normalização lógica do tamanho da surface de captura sob zoom negativo do Desktop; 2026-08-03 suplementa a semântica de cancelamento do gesto de arraste quando a janela perde o foco durante o arraste; 2026-08-05 suplementa a semântica de estabilidade do primeiro frame do Fit ao alternar entre múltiplos tabs; 2026-08-30 suplementa a persistência das preferências de exibição do navegador humano entre reinicializações e o isolamento do Agent Browser Use)
Status: implementado

## Concept Map And State Owners

```text
Botão responsivo da BrowserToolbar
  -> UnifiedBrowserView.isResponsiveMode (estado React local do tab atual)
  -> ResponsiveBrowserViewport.viewportSize (estado React local do tab atual)

  -> o mesmo guest <webview> recebe o resize de viewport
  -> resize da página / media query

  -> responsive: restaura width / height / previewZoom

Toggle / input válido / drag / zoom do human
  -> atualiza o runtime local do renderer do tab atual
  -> grava de forma combinada a preferência de exibição em AppSettings (o arraste de tamanho usa trailing debounce)
  -> o setting service persiste no setting.json global do app
  -> tabs existentes -X-> não são reinicializados por broadcast de settings

Criação pelo Agent Browser Use / viewport set / reset / evento do renderer
  -> continua usando BrowserGuestManager + runtime por tabId
  -X-> não lê a preferência de exibição do AppSettings
  -X-> não grava a preferência de exibição do AppSettings

Barra de ferramentas do viewport responsivo
  ├─ input de width / height --inteiro válido--> responsiveViewportSize
  │                                      └-> sincroniza o viewport do guest de um único tab
  └─ select de zoom --> previewZoom do tab atual
          ├─ percentual fixo --> visualScale
          └─ Fit to window + ResizeObserver do canvas --> min(widthRatio, heightRatio, 1)
                                                    └-> apenas transform no renderer

visualScale do renderer
  -> footprint escalado da tela + transform estável do frame
  -> delta de arraste do pointer / visualScale
  -> tamanho do viewport CSS
  -X-> viewport / captura / media query do BrowserGuestManager (não afetado pelo visualScale)

Prazo de operação do Agent
  -> useBrowserResizeOperationWarning
  <- ResizeObserver do pane externo ou resize responsivo manual
  -> aviso fraco apenas no renderer + brilho do webview

Agent tab.setViewportSize({ width, height })
  -> BrowserCommand(browserViewportSet, tabId)
  -> host/main BrowserGuestManager (valida por workspace/session/browser/tabId)
  -> device metrics override do CDP em um único guest (viewport CSS + deviceScaleFactor=1)
  -> BrowserViewViewportChanged(tabId, viewport) no renderer dono
  -> UnifiedBrowserView entra automaticamente na livre dimensão e sincroniza o frame estável
  -> o resize manual do renderer grava de volta o override do mesmo tab

newTab explícito do modelo / createTab implícito quando não há tab existente
  -> o BrowserGuestManager grava o viewport override 1280 × 720 na criação do tab
  -> o renderer monta um <webview> estável e anexa o guest
  -> o main aplica as métricas do CDP nesse guest e notifica o renderer dono
  -> o UnifiedBrowserView entra em 1280 × 720 na livre dimensão com Fit

Criação de tab pelo usuário / claim ou navegação pelo modelo em tab existente
  -> o tab do usuário é montado com viewport override = undefined (tamanho normal)
  -> claim/activate/navigate/reload não grava viewport
  -> mantém o modo normal/free-size e o tamanho real anteriores à ação
  -> só o toggle/input/drag do usuário ou o viewport set/reset explícito do Agent muda o tamanho

browser.tabs.list()
  -> o BrowserGuestManager lê o viewport CSS real por tab
  -> BrowserTabSummary.viewport
  -> BrowserTabInfo.viewport
  -> tabs.get(info.id).viewportSize()

tab.screenshot()
  -> guarda de screenshot in-flight por tab
  -> Page.getLayoutMetrics seleciona apenas o clip CSS, ignorando backing/CSS legados
  -> CDP Page.captureScreenshot(scale=1, captureBeyondViewport=false para captura de viewport)
  -> lê as dimensões do IHDR do PNG
  -> igual ao clip CSS alvo: retorna a primeira captura
  -> divergência uniforme: adjustedScale = firstScale × targetSize / actualSize
  -> repete o Page.captureScreenshot uma vez e escolhe o resultado mais próximo do alvo
  -> sub-orçamento de 30s host→main
  -> sucesso: limpa o in-flight; no modo livre dimensão os pixels de saída são 1:1 com o viewport CSS
  -> timeout externo: retorna timeout estruturado; novos screenshots antes do settle falham explicitamente e não são despachados de novo
  -> conclusão tardia: limpa o in-flight, e os screenshots seguintes são restaurados

wheel do guest (apenas consumido pelo host no modo livre dimensão)
  -> existe um ancestral rolável no guest para a direção correspondente: fica com a página
  -> não há ancestral rolável no guest e a página não chamou preventDefault
  -> preload fixo `sendToHost(wheel-boundary, deltaX/deltaY)`
  -> `ipc-message` do `<webview>` do embedder
  -> `scrollBy({ left: deltaX, top: deltaY })` da tela responsiva
```
