# Roteiro E2E de Decisões de Conversation Session

> **Nota de status**: este documento é um roteiro de pendências, não a lista de cobertura atual. Os
> nomes de arquivo spec sugeridos nas linhas `ready-to-write` podem ainda não existir; somente os
> testes existentes apontados pela coverage matrix e seus status constituem fato de cobertura.

Objetivo: mapear previamente os cases da área de sessão que ainda não estão `covered` para os pontos
de entrada de E2E posteriores. Este documento não decide por produto; ele especifica "onde escrever os
testes uma vez confirmada a decisão de produto, de que fixture/harness é preciso e quais faces de
observação usar para aceitar".

## Definição de Status

| Status                          | Significado                                              |
| ------------------------------- | -------------------------------------------------------- |
| `blocked-by-product-decision`  | Decisão de produto não confirmada; só se manter o plano de implementação de teste |
| `ready-to-write`                | Decisão de produto confirmada; já se pode começar a escrever o E2E |
| `implemented`                   | Já há evidência de automação E2E independente; pode ser devolvida à coverage matrix |
| `ignored`                       | Produto confirmou que a versão atual não cobre |
| `invalid`                       | Produto confirmou que a combinação é podada por regras prévias |

## Relação de Status com a Matriz de Cobertura

O script de auditoria alinha mecanicamente este roteiro com a coverage matrix de caminho principal /
fault:

| Coverage status                 | Roadmap status                |
| ------------------------------- | ----------------------------- |
| `undefined` / `decision-needed` | `blocked-by-product-decision` |
| `missing` / `planned`           | `ready-to-write`              |
| `failing` / `partial`           | `implemented`                 |
| `ignored`                       | `ignored`                     |
| `invalid`                       | `invalid`                     |

Quando um case passa a `covered` na coverage matrix, ele deixa de precisar aparecer neste roteiro.
