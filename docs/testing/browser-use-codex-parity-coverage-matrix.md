# Matriz de Cobertura Browser Use

> Objetivo: transformar as combinações de `iab | extension | cdp`, seleção, API, segurança, ciclo de vida e estado multi-plataforma em aceitação executável; evitar declarar conclusão após testar apenas o caminho feliz.

O escopo inicial, as regressões históricas e o corte da E2E oficial do Desktop WDIO estão em
`docs/browser-use/2026-07-19-desktop-iab-e2e-spec.md`. Na matriz, "automação" por padrão pode ser apenas unit, contract
ou um smoke manual pontual; somente os casos que listam explicitamente `packages/desktop/test/e2e/...` no estado contam como E2E oficial do Desktop.

## 1. Dimensões de estado

| Dimensão      | Valores                                                                                            |
| ------------- | -------------------------------------------------------------------------------------------------- |
| Backend       | none / iab / extension / cdp / iab+extension / extension multiinstância / all                        |
| Entrada de seleção | exact id / type alias / default / URL local / URL exact tab / URL host hierarchy / invalid URL |
| Client mode   | desktop-continuous / web-remote-replayable                                                         |
| Workspace     | local / SSH / WSL / Docker / mesmo path com identidade diferente                                   |
| Runtime       | fresh kernel / warm kernel / timeout reset / sandbox reset / session close                         |
| Origem da tab | agent-created / claimed user tab / unclaimed user tab / restored / stale                           |
| Ciclo de vida da tab | open / active / background / handoff / deliverable / finalized / closed                     |
| Família de API | navigation / playwright / cua / dom_cua / content / clipboard / dev / dialog / capability             |
| Segurança     | read-only / preapproved / action-confirm / denied / attempted bypass                                |
| Saúde do backend | healthy / unavailable / handshake timeout / disconnect / reconnect / stale generation              |
| Resultado     | direct value / bytes/image / response meta / structured error / uncertain side effect               |

O produto cartesiano completo é inexecutável; adotamos agrupamento por fronteira, pairwise e combinações por prioridade de risco. Nenhum corte pode remover os casos cruzados de identidade de backend, clientMode, identidade de workspace, deny de segurança ou limpeza de ciclo de vida.

## 2. Decisões de corte

| Combinação                                        | Decisão            | Justificativa                                      |
| ------------------------------------------------- | ----------------- | -------------------------------------------------- |
| Playwright como backend                           | cortar             | Erro conceitual; Playwright é uma família de API  |
| extension/cdp retornando stub em fase não implementada | proibido        | Criaria falsa disponibilidade                       |
| runtime de backend mobile próprio                 | cortar             | Viola a restrição de shared-host attachment        |
| relay/main mantendo estado de tab/task            | cortar             | Viola a arquitetura de controle remoto             |
| remote isolado apenas por workspacePath           | proibido           | Exige workspaceIdentity/remoteSessionId           |
| Combinação completa de cada OS × cada método de API | pairwise           | As diferenças de OS se concentram em instalação/native host/caminhos/atalhos |
| Combinação completa de cada versão de navegador × cada locator | pairwise | Preservar stable/beta e locator/action críticos |
| Todas as ações quando o CDP está desligado       | testar apenas invisível/não selecionável | Membro/backend não suportado precisa estar oculto |
| Nova tentativa por outra família de API após deny | obrigatório        | Previne bypass do limite central de segurança      |

## 10. Portão de promoção para E2E

Antes de qualquer Slice entrar em "concluído":

1. O caso correspondente muda de "a implementar" para o caminho e o resultado do caso automatizado, e não apenas o texto de status.
2. Mudanças de protocolo precisam de strict schema com exemplos positivo e negativo, compatibilidade com chamadas antigas e teste de correlação de ponta a ponta.
3. Casos de interação/controle remoto precisam indicar o impacto em desktop continuous e web replayable.
4. Extension/CDP não podem ter a conclusão provada apenas com mock; é necessário ao menos um smoke E2E com Chrome real/CDP real.
5. API manifest, grafo de objetos em runtime e documentação precisam de testes de consistência snapshot/contract.
6. É obrigatório rodar `pnpm typecheck` e `pnpm lint`, e registrar os riscos de ambiente (OS, assinatura, remoto) que não foi possível cobrir.
